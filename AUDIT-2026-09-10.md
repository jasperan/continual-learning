## Security Findings

| Severity | Location | Issue | Status | Remediation |
|---|---|---|---|---|
| High | `src/continual_learning/doc2lora/trainer.py:251` | `torch.load(path, weights_only=False)` on a checkpoint supplied via `--resume` (or any shared/downloaded `.pt`). The unrestricted pickle unpickler executes arbitrary code embedded in the checkpoint. Confirmed exploitable: a payload whose `__reduce__` returns `(eval, ("1+1",))` is executed by `weights_only=False` and rejected with `UnpicklingError` by `weights_only=True`. | fixed | `weights_only=True`. The checkpoint written by `save_checkpoint` contains only state dicts, optimizer/scheduler state, `log_history` and `step` — all tensors/primitives, so the restricted unpickler is sufficient. Verified by the existing save/load round-trip test. |
| High | `src/continual_learning/checkpointing/manager.py:83` | Same unsafe-deserialization class: `torch.load(cp_dir / "tfidf_stats.pt", weights_only=False)`. TF-IDF gate state is written by `TFIDFGate.state_dict_custom()` as `{idf_scores: Tensor, doc_freq: Tensor, num_docs: int, threshold: float}` — no custom objects were ever required. Loading a tampered checkpoint runs attacker pickle code. | fixed | `weights_only=True`; verified `test_manager.py::test_load_restores_weights` and the full suite still pass. |
| Low | `src/continual_learning/cli/main.py:30` | `os.system("cls" if os.name == "nt" else "clear")` flagged HIGH as `os_system`. The command is a string literal selected only by `os.name`; no variable interpolation and no user input reaches it. Command injection is not possible. | documented (dismissed as benign) | No change (behavior-preserving). Could use `rich.console.Console.clear()` to drop the shell call entirely if desired; not a security fix. |
| Low | `src/continual_learning/data/oracle_docs.py:69` | SSRF surface: `fetch_and_process(url)` calls `requests.get(url, timeout=30)` with no scheme/host restriction. An attacker who can control the `url` argument could reach internal endpoints (e.g. cloud metadata `169.254.169.254`). Reachability today is nil: the only caller is `scripts/validate_gpu.py` which passes the static `ORACLE_DOC_SOURCES` dict. | documented | Not fixed: an allowlist changes the public helper's contract (design decision). Recommended fix: parse with `urllib.parse.urlparse`, allow only `http`/`https`, and optionally restrict hosts to `docs.oracle.com`. |
| Low | `src/continual_learning/ace/ollama_client.py:25` | `urllib.request.urlopen(req)` has no timeout, so a hung/malicious Ollama endpoint stalls the CLI indefinitely. `base_url` comes from config, not remote input, so this is a reliability/DoS-hardening item, not a remote-injection issue. | documented | Recommended fix: pass `timeout=` and surface a clear error. Not changed to avoid altering user-visible behavior on slow local models without a decision. |
| Low | `src/continual_learning/checkpointing/manager.py:33,75`; `src/continual_learning/ace/engine.py:117,127` | Path traversal via the user-supplied `name`: `cp_dir = self.checkpoint_dir / name` and `os.path.join(self.playbook_dir, f"{name}.json")` accept `../` segments, allowing write/read outside the intended directory. Not a privilege boundary: the operator typing the name already runs as the same user and can write those paths directly. | documented | Recommended fix: validate `name` against `^[A-Za-z0-9._-]+$` (reject `..`/separators) in `CheckpointManager.save/load` and `ACEEngine.save_playbook/load_playbook`. |
| Informational | `src/continual_learning/ace/generator.py:10`, `reflector.py:20`, `curator.py:26` | Prompt-injection surface: learned document text is interpolated into LLM prompts, and reflector/curator parse model JSON output to mutate the playbook. Impact is bounded — the parsed output is treated as text strategies only; there is no tool-calling, code execution, or file/network side effect driven by it. | documented | Acceptable as designed. If documents become untrusted, isolate instructions from data and validate playbook patches against a schema. |
| Informational | `src/continual_learning/config.py:77` | `save_config` always writes back to the repo-tracked `configs/default.yaml` (the CLI "Configure" menu mutates a tracked file) rather than a user config location. No secret is stored; local-only. | documented | Recommended: write to a user config dir, or document that this edits the checked-in default. |
| Informational | `src/continual_learning/cli/main.py:59` | `except Exception: pass` (scan `bare_except_pass`) around the VRAM probe. This is intentional best-effort telemetry; failure must not abort the menu. | documented (dismissed) | No change. |

## Deslop Applied

All items below are behavior-preserving and were verified by the full test suite.

- `src/continual_learning/checkpointing/manager.py`: removed `import os`; the module only uses `pathlib.Path` (ruff F401).
- `src/continual_learning/doc2lora/meta_dataset.py`: removed unused `import json` and `from pathlib import Path` (ruff F401). `MetaTrainingDataset`/`SyntheticMetaDataset` use only `random`, `Optional`, and `Dataset`.
- `scripts/validate_gpu.py`: removed `chunk_text` from the `oracle_docs` import in `validate_milestone_5` — never referenced (ruff F401).
- `scripts/validate_gpu.py`: removed the dead `batch_losses = []` accumulator and its only write (`batch_losses.append(loss)`). The list was never read; the callback's `print` and signature are unchanged.
- `scripts/train_hypernetwork.py`: removed the `rich.progress` import inside `if use_rich:` — identical names were already bound by the guarded import at the top of `main()`, so this shadow import was redundant.

Not changed (deliberately, to keep the diff surgical despite being "slop"-adjacent):

- 7 × `f-string without placeholders` (ruff F541) in `src/continual_learning/cli/main.py` (3) and `scripts/validate_gpu.py` (4). Purely a redundant `f` prefix; classified as style, not removal of behavior or dead code, and left to avoid a style sweep.
- The 6× duplicated "prompt for a document path, check existence, read file" block in `cli/main.py` (`handle_learn_document`, `handle_jitrl_mvp`, `handle_jitrl_full`, `handle_ace_learn`, `handle_doc2lora_learn`, `handle_compare_engines`). Extraction would be behavior-preserving but is a larger refactor across untested CLI handlers; noted in Full Review instead.
- `handle_outer_loop` / `handle_forgetting` stubs in `cli/main.py` print "not yet implemented" but are wired into the live menu, so they are reachable, not dead.

## Full Review Findings

Ranked by impact (read-only; no code changed for these):

1. **`Doc2LoRAEngine` silently ignores `simulated`** — `src/continual_learning/doc2lora/engine.py:32` accepts `simulated: bool = False` and never reads it; line 44's TODO confirms both modes use `SimulatedHypernetwork`. `configs/default.yaml` sets `doc2lora.simulated: false`, so a user who believes they are running the real Perceiver hypernetwork gets hash-seeded random LoRA weights. Correctness/expectation bug. Recommend raising `NotImplementedError` for `simulated=False` or wiring `PerceiverHypernetwork` + `checkpoint_utils.download_checkpoint`.
2. **`--batch-size` is accepted but unused** — `scripts/train_hypernetwork.py:58` parses `--batch-size`; the loop at lines ~300-306 calls `trainer.train_step(...)` on a single item per step, and `HypernetworkTrainer` has no batch parameter. The flag is silently ignored. Remove it or implement batching.
3. **Dead-but-tested production API** — `LogitModulator` (`src/continual_learning/jitrl/full/reward.py:25`) is no longer used by `JitRLFullEngine` after the "compute bias once" optimization (the module docstring of `_RewardLogitsProcessor` documents the replacement), yet it is the subject of `tests/test_jitrl/test_full_reward.py`. Likewise `KnowledgeStore.get_token_embeddings` / `_doc_token_embeddings` (`knowledge_store.py:38`) are unused by any production path. Removing would change public API and delete tests, so this is flagged rather than changed.
4. **Duplicated logic** — `_BiasLogitsProcessor` (`src/continual_learning/jitrl/mvp/engine.py:7`) and `_RewardLogitsProcessor` (`src/continual_learning/jitrl/full/engine.py:7`) are byte-identical in `__call__` (`return scores + self.bias.to(scores.device)`). A single shared private processor would remove the copy. Low risk but touches two engines.
5. **CLI duplication** — the document-read block is repeated six times in `src/continual_learning/cli/main.py` (see Deslop Applied). Maintainability cost, zero test coverage on the affected handlers.
6. **Test coverage gap** — `tests/test_cli/test_main.py` only covers `build_menu_choices` and `format_status_panel`; the ~25 menu handlers (including checkpoint save/load and engine wiring) are untested. `test_doc2lora/test_trainer.py` does cover the checkpoint round-trip that the security fix relies on.
7. **`install.sh` is stale after the uv migration** — `install.sh:90` runs `pip install -e ".[dev]"`, but `pyproject.toml` declares dev tooling in a PEP 735 `[dependency-groups]` table, which pip does not understand as an extra. The `|| pip install -e .` fallback masks the failure, so `pytest`/`ruff`/`cov` end up missing. The project now ships `uv.lock` and was migrated to uv (`0cbedcd`), but the installer still builds a venv with pip.
8. **Broad exception swallowing in `ensure_model_loaded`** — `src/continual_learning/cli/main.py:154` catches `Exception` and only prints; acceptable for an interactive CLI, but it hides programming errors (e.g. a bad config key) as "Failed to load model". Consider narrowing to import/runtime errors.
9. **Nondeterministic iteration** — `MetaTrainingDataset.contexts` (`doc2lora/meta_dataset.py:79`) returns `list(set(...))`, so ordering varies run to run. Minor; sort if callers ever depend on it.
10. **Dependency/version hygiene** — runtime deps in `pyproject.toml` are unpinned (`torch`, `jax`, `jaxlib`, ...), relying on `uv.lock`; that is acceptable for an app. `.pre-commit-config.yaml` pins `ruff-pre-commit v0.9.0` while the working env has ruff 0.15.13, and the tree currently has 164 ruff violations (mostly import order/E501/F541), i.e. the hook is not being enforced on the current files. Consider `ruff` version alignment and a cleanup pass in a dedicated change.
11. **`handle_configure` mutates a tracked file** — the "Configure" menu calls `save_config`, which writes `configs/default.yaml` (`config.py:77`), producing a dirty working tree after a normal user action. Overlaps with the Informational security finding above.

## Remaining Risks

- The two `weights_only=True` changes were validated against checkpoints produced by this codebase and by unit round-trip tests. A checkpoint written by an older external tool containing non-tensor Python objects would now fail to load; no such producer exists in this repo or its documented workflow, but users resuming from a hand-crafted `.pt` would see a load error rather than silent code execution.
- SSRF in `oracle_docs.fetch_and_process`, the missing Ollama timeout, and checkpoint/playbook name path traversal are documented but **not fixed** (they need an API-contract or input-validation decision). No test currently exercises them.
- No authentication/authorization or network-server review is possible/necessary: the package has no server component; the `interactive/` app is a static Next.js export (`output: "export"`) with no API routes.
- Prompt-injection through learned documents into Ollama prompts is inherent to the ACE design and was only reasoned about statically; no dynamic adversarial test was run.
- The full 164-error ruff baseline was not cleaned (out of scope; would be a mass style change). F541 and the remaining I001/E501/N806 are untouched.
- The Next.js frontend was not built or type-checked in this audit (`interactive/node_modules` is absent and no tests exist). Its audit is source-reading only.
